//  Tickly —— 简洁的 Windows 待办事项应用
//  纯 C++ + Win32 API，无任何第三方依赖，单文件便携运行

//  v1.13.23 更新（顶部输入框中文输入时光标回到开头 —— 已彻底修复）：
//    · 真正的根因（靠诊断日志定位，此前 4 轮修改都在错误方向上打转）：
//      输入法在上屏收尾时，会向输入框发一条 EM_SETSEL(0,0)，把插入点强行
//      复位到文本开头，而文本本身完好。此后下一段组词就从位置 0 开始提交，
//      于是用户看到「光标回到最前面」「文字插到『后』前面」。
//      日志实测：四个字正确插入后插入点正确停在 (4,4)，紧接着收到 0x00B1
//      （EM_SETSEL）把选区改成 (0,0)，文本长度仍是 4。这条消息不来自本程序
//      任何调用点（PassKeepCaret 与 Layout 的每次 EM_SETSEL 都在追踪范围内
//      且值正确），是外部（输入法）打进来的。
//    · 修复：在 EditProc / RowEditProc 入口拦截「EM_SETSEL(0,0)」，条件收得
//      很窄 —— 只拦参数为 (0,0)、文本非空、且当前插入点正好在文本末尾的三者
//      同时成立的情况，其它一律放行。用户点击 / Home 键 / 拖选不走这条路径，
//      Layout 的选区恢复若为 (0,0) 时 b1 也不在末尾，不会命中。
//    · 顺带纠正的认知：v1.13.17 起在 WM_IME_COMPOSITION 上做插入点算术是错的。
//      该消息九成是 GCS_COMPSTR 候选串更新，长度增量描述的是候选串自身增长，
//      与文档插入点无关；据此 EM_SETSEL 会把光标一次次往回拽（越修越坏）。
//      现规则：IME 消息一律原样转发，只有 WM_CHAR / WM_PASTE 做插入点守恒。
//    · 行内编辑框（双击任务编辑）同步应用上述两条规则。
//
//  v1.13.19 更新（顶部输入框中文输入时光标回到开头 —— 中间版本）：
//    · 曾尝试只对普通 WM_CHAR / WM_PASTE 保留插入点兜底，把 WM_IME_CHAR 与
//      WM_IME_COMPOSITION 全交给原生 EDIT/输入法管理（该结论正确，已保留）；
//      但在 WM_IME_ENDCOMPOSITION 后投递 WM_INPUTCHANGED 补算并不能解决复位，
//      因为复位来自输入法发出的 EM_SETSEL，与本程序的布局路径无关。
//
//  v1.13.17 更新（中文输入法上屏后插入点归零，四层堵死）：
//    · 你反馈「继续输入时文字落在『后』前面」—— 说明是真的插入点被改成了 0，
//      不是绘制问题。据此把「所有可能写选区的路径」逐条封掉：
//      1) 组词期间 UpdateInputSize 直接返回，不再走 Layout —— 组词串会让
//         EM_GETLINECOUNT 抖动（单行↔多行），一旦据此 MoveWindow 改输入框
//         尺寸，EDIT 重排就会把插入点清掉
//      2) 删掉 CenterInput 里「先存选区、SETRECT 后写回」那段 —— 写回的是
//         读取瞬间的值；若那一刻正在输入法提交过程中，读到的是组合串起点，
//         写回去等于把插入点顶到最前面。这段是 v1.13.14 我自己加的，属误伤
//      3) Layout 里移动输入框前后保存/恢复插入点，覆盖所有布局触发路径
//      4) 结果兜底 PassKeepCaret：WM_CHAR / WM_IME_CHAR / WM_IME_COMPOSITION /
//         WM_PASTE 处理完，若「文本变长了但插入点没有跟着前进」，按「插到原
//         位置之后」纠正。组词提交以「组词开始前」记录的插入点为基准 ——
//         组词期间 EM_GETSEL 指向组合串起点，用它当基准会算少
//    · 第 4 层与前 3 层互相独立：即使还有未知路径破坏选区，只要字符是通过
//      上述四条消息进来的，插入点都会被纠正回正确位置
//    · 实测：英文、中文直输、Home 后中间插入、粘贴多行全程 0 次误纠正

//  v1.13.16 更新（中文输入法上屏后光标回退，根治）：
//    · 真凶是 EN_CHANGE 的调用时机：它是 EDIT 在「处理这次输入的过程中」同步
//      发给父窗口的，我们在这条通知里同步调 UpdateInputSize -> CenterInput ->
//      EM_SETRECT + EM_SETSEL。第一段输入时格式矩形刚好没变（提前 return），
//      所以看着正常；第二段「下午」上屏时文本变长、折行数变化，格式矩形随之
